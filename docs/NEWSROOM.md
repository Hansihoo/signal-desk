# Signal Desk 뉴스룸과 에이전트 소식 탐지

2026-10-14 사용자는 AI Witness처럼 소식을 읽고 찾는 홈페이지와 기사 구성을 요청했다. 이미 AI를 업무에 사용하는 독자가 주요 기업의 발표와 도구 변경을 빠르게 찾게 하는 기능이다. 수치 분석은 기존 보고서 형식을 유지한다.

## 화면과 글의 두 형식

- Home `preview/index.html`: 최대1,400px의 홈에 기업·주제 탐색, 검토 기사, 한국어 최신 소식·도구 업데이트를 배치한다. 기존 보고서의 최근 변경과 검색 보드는 아래에 있다.
- AI 소식 `preview/news.html`: 한국어 기사만 날짜순으로 제공하며 기업/출처와 종류 필터, 검색, 20개씩 페이지 이동, 탐지 상태를 제공한다. 원어 탐지는 `preview/news-sources.html`로 분리한다.
- 기사 `preview/articles/<article-id>.html`: 제목과 짧은 설명, 원문 발표일, 핵심 사건을 먼저 말하는 도입, 배경과 업무 의미, 사용 조건, 원문 링크.
- 원문 소식 `preview/articles/news-<row-id>.html`: 이전 숫자 링크의 호환 경로다. 같은 원문의 한국어 본문이 있으면 그 본문을 보여 주며 없으면 원문으로 이동한다. 새 탐지 목록은 내부 빈 페이지로 연결하지 않는다.
- 수치 보고서와 모델 비교: 기존 report-v1, 측정 조건, 표, 차트, 이전 판과 실제 내용 검토일을 유지한다. 새 기사를 보고서 숫자에 합산하지 않는다.

AI Witness의 섹션 배치와 기사 연결을 참고했고 브랜드·번역·본문을 복제하지 않았다. 공유 Editorial shell과 기존 Pretendard를 재사용한다. 참고 페이지와 공식 원문의 날짜가 다를 수 있다. 예를 들어 AI Witness의 Scion 소개는 10월14일이고 Anthropic 원문 발표는 10월13일이다. 직접 작성한 기사는 공식 원문의 날짜를 사용한다.

신규 기사의 규칙은 [글쓰기 기준](RESEARCH_WRITING_GUIDE.md)의 2026-10-14 항목에 있다. 숫자가 등장하는 뉴스와 여러 조건의 수치를 분석하는 보고서를 같은 형식으로 강제하지 않는다. 뉴스에서도 공급사 주장과 적용 조건은 보존한다.

## 수집, 변경과 실패의 의미

새 `agent-news` 수집은 기존 AI 뉴스의 전체 점수 상한과 독립적이다. 특정 피드의 잦은 빌드가 다른 주요 기업의 새 항목을 저장 전에 밀어내지 않게 출처별 후보를 저장한다. 같은 URL과 같은 내용이면 `inserted=0`, `updated=0`; 발견/성공 시각과 내용 변경을 구분한다. 원자료는 내용 지문별로 보관해 동일 바이트를 매번 복제하지 않는다. ETag/Last-Modified가 있으면 조건부 요청을 사용한다.

기존 `news_items.first_seen_at`은 처음 발견한 실제 시각이고 `last_seen_at`은 재관찰 시각이다. 발표일을 수집 시각으로 만들지 않는다. Atom은 published를 우선 읽고, 없으면 updated를 사용하므로 원문 미리보기는 ‘출처 날짜’로 표시한다. 직접 작성한 기사의 원문 발표일과 구분한다. `agent_news_sources`는 목록 URL, 최근 시도/성공, 오류와 목록 수를 저장한다. 실패나 파서가0항목을 반환하면 이전 뉴스와 마지막 성공 기록을 보존한다. 목록 확인은 원문 전체 검토와 다르며 화면에도 구분한다. 재생성은 기사 검토일을 갱신하지 않는다.

동일 URL이 기존 수집기와 새 경로에 모두 있으면 화면의 처음 발견한 날짜는 보존된 두 기록 중 가장 이른 실제 시각을 사용한다. 기존 저장 행을 새 경로의 수집일로 덮어쓰지 않는다.

기사 본문은 `newsroom_articles`, 과거 판은 `newsroom_article_revisions`에 저장한다. 동일한 입력의 재등록은 판·수정일을 바꾸지 않는다. 바뀐 기사는 새 판으로 저장하고 이전 기사 링크를 만든다. [초기 기사 입력](../config/newsroom_articles.2026-10-14.json)은 공식 원문을 직접 읽고 작성한 초기3편과 10월15일 보강6편이다. 문단별 출처와 원문/검토일을 검증한다. 독립 에이전트나 사람의 독해 시험을 거쳤다고 표시하지 않는다.

## 빠른 반복 탐지의 운영 상태

[agent-news.yml](../.github/workflows/agent-news.yml)은 매시23분 UTC의 설정이다. 기존 일일 모델/주거 수집은 유지하고 별도 빠른 경로에서 agent-news만 탐지한다. 변경이 없는 실행은 사이트 재생성과 상태 자산 생성을 생략한다. 새 항목·내용 변경·실패/복구 상태 변화가 있으면 상태 저장과 Pages 반영을 수행한다. 기존 workflow와 동일한 concurrency group으로 상태 경합을 막는다. 스케줄은 정확한 실시간 알림이 아니라 목표 주기다.

변경 없는 원격 실행은 로그에만 남으므로 공개 화면의 ‘최근 탐지’는 마지막으로 반영한 상태의 확인 시각이다. 모든 시간별 재확인 시각을 사이트에 표시하는 방식은 아니다. GitHub Actions 지연·실패와 각 공급사의 목록 게시 지연도 있어 즉시 탐지를 보장하지 않는다. 검토 기사는 편집 입력이며 수집만으로 한국어 집필을 끝낸 것으로 표시하지 않는다. 새 원문·릴리즈의 탐지는 원문 목록에 자동 반영한다.
