## 누구에게 무엇을 가르치는지에 따른 기준

독자는 개발 또는 업무 관리 경험은 있지만 해당 AI 기술을 처음 배우는 사람으로 잡았다.
터미널·Python·GitHub App 등의 선행 지식이 필요하면 그 조건을 평가에 반영했다.
모든 글에 코드를 요구하지 않는다. 개념 글은 동작을 설명할 수 있어야 하고,
계산 글은 값을 바꿔 계산할 수 있어야 하며, 제작 글은 결과물을 만들어 확인할 수 있어야 한다.
지원 공고는 신청 후보를 선별할 수 있으면 목적에 맞는 참고자료가 된다.

1. 제목과 요약에서 대상·배울 내용·활용 장면을 알아볼 수 있는가?
2. 핵심 원리가 결과 이전에 설명되는가? 용어 정의만 나열하지 않는가?
3. 같은 사례의 입력 → 중간 처리 → 결과 → 실패 원인이 연결되는가?
4. 글이 약속한 이해·판단·행동에 필요한 단계가 본문에 있는가?
5. 다른 입력이나 업무에 적용할 수 있는가? 풀이에서 이유를 확인할 수 있는가?
6. 가상 사례·관측 결과·공식 조건·편집 권고의 경계가 지켜지는가?

주 판정은 세 가지다. **교육 활용 가능**은 한정된 목표의 설명이 성립한다는 뜻이고,
**교육 보강 필요**는 핵심 연결이 빠졌다는 뜻이다. **참고 브리핑**은 다른 목적의
유용한 글이라는 뜻이다. 글의 길이·장 수·코드 블록 수로 판정하지 않았다.

## 가장 중요한 보강 순서

### 1. 실제 선택을 오도할 수 있는 모델 비용·추천부터

종합점수에서 업무별 기본 모델로 넘어가는 권고가 먼저다.
경고를 늘리는 것보다 표와 결론을 **확인된 관측 / 가정한 계산 / 아직 검증하지 않은
운영 제안**으로 실제 내용에 맞춰 분리해야 한다.

벤치마크의 과제 집합은 다르다. 예를 들어 한 모델의 DeepSWE 63%와
SWE-Atlas-QnA 33% 차이만으로 ‘구현보다 방향 설정이 약하다’고 확정하면
서로 다른 시험의 난이도를 능력 차이로 취급할 수 있다. 같은 하위 평가에서
후보끼리 비교한 뒤, 주장하려는 업무의 동일 조건 시험으로 이어가야 한다.
평가판·구성 과제·측정 방식도 바뀔 수 있다.
[Artificial Analysis 공식 방법론](https://artificialanalysis.ai/methodology/coding-agents-benchmarking/)은
현재 지수의 서로 다른 세 과제군과 버전 변경을 설명한다. 이를 근거로 한
위의 과잉 일반화 우려는 이번 검토자의 편집 판단이다.

### 2. RAG의 검색 원리를 실제 작은 자료로

현재의 구판/정답 검증 사례는 유지한다. 여기에 원문 세 문단, 나눈 단위,
검색 질문, 반환된 후보와 순서, 선택된 근거, 답을 붙인다.
의미가 비슷한 표현을 찾는 과정과 필터·버전 제한의 역할을 설명해야
‘문서를 넣으면 답한다’보다 한 단계 깊이 이해할 수 있다.

### 3. 해커톤 제작 글의 약속을 끝까지 이행

현재 Python 필터는 첫 실습으로 쓸 수 있다. 모델에 도구를 알리는 선언,
도구 요청 수신, 실제 함수 실행, 결과 반환, 최종 답과 원문 표시가 빠져 있다.
환경·버전·명령·기대 출력·실패 진단을 포함한 한 경로를 완성하거나,
현재 글을 학습 로드맵이라고 정직하게 한정해야 한다.
Marketplace 제작과 API 이전 글에도 같은 문제가 있다.

### 4. 새 주제의 실제 교재 확보

현재 사이트에는 온톨로지, 지식베이스 설계·갱신, FDE의 현장 역할,
AI에 따른 직무·채용·관리 변화에 관한 독립된 교육 글이 없다.
수집 운영 문서와 출처 목록에 들어 있다는 사실은 게시된 교육 내용의 존재를 뜻하지 않는다.
Upwork의 과거 플랫폼 수입 증가율만으로 현재 인력시장 전체를 설명할 수 없다.
이 주제는 실제 시스템 구조·현장 역할·측정 시기와 모집 요건 등 다른 증거를 수집해야 한다.

### 5. 글들 사이에 선행 지식과 학습 결과 연결

공고를 선별하는 글을 초보 제작 교재로 채점할 필요는 없다.
대신 개념 입문 → 작은 실행 → 오류와 검증 → 도입 판단의 경로를 마련하고,
각 글이 무엇을 익히며 어떤 선행 글이 필요한지 편집 문서에서 관리한다.
MCP Apps의 새 판과 평가·용량·문서 도입 사례는 이 경로의 재료로 활용할 수 있다.
디자인이나 장 제목을 바꾸는 것보다 이 연결이 먼저다.

## 다시 검토할 때의 완료 조건

- 각 글의 독자 질문·선행 지식·배운 뒤 가능한 행동을 먼저 정한다.
- 개념 글은 새로운 사례의 결과와 실패 위치를 이유와 함께 설명할 수 있게 쓴다.
- 실습 글은 정해진 환경에서 명령과 코드를 따라 기대 결과를 재현할 수 있어야 한다.
  개념 예제를 실행 검증된 실습이라고 표시하지 않는다.
- 판단 글은 관측·조건·불확실성으로 실제 선택을 좁힐 수 있게 한다.
- 제목·요약은 완성된 설명에서 다시 추출하며 본문보다 큰 약속을 하지 않는다.
- 의미·근거 검토, 독자 관점의 이해 검토, 실행·출력 검증을 따로 기록한다.
  실제 독자에게 읽히지 않은 상태를 독자 이해 검증 완료라고 쓰지 않는다.
- 보강할 때는 기존 판을 보존하고 새 불변 배치로 발행한다.

이번 전수 검토는 완료했지만 **전체 글의 교육 품질 승인은 보류**한다.
위 판정은 이후 보강의 시작점이며 내용 수정·배포 완료 보고가 아니다.
