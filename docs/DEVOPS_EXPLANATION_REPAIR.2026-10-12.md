# DevOps의 정의와 필요성을 먼저 설명하기

독자는 r6 첫 장의 두 가상 예시가 갑자기 나온 이유를 알 수 없다고 지적했다. 해당 장의 질문은 DevOps가 무엇이고 왜 필요한가인데, 가격 정렬 오류의 원인과 해결 절차가 개념과 필요성의 설명을 대신했다. 앞선 자체검토 Pass는 이 사용자 피드백을 반박하는 근거가 아니다.

## 요약

첫 장에서 세 가상 예시 블록을 제거하고 개발과 운영의 역할, 필요한 변경과 안정적인 사용의 관계, 정보 단절의 문제, 협업과 자동화 및 피드백의 관계를 설명한다. 요약에도 필요한 이유를 추가했다. 정렬 사례는 CI/CD의 구분과 뒤의 실습에서 사용하며, 사례 안에서 목적과 가정부터 밝힌다.

독자는 처음 DevOps를 배운다. 읽은 뒤 개발과 운영이 서로 어떤 정보를 알아야 하는지, 반복 작업을 자동화해도 공동 기준과 대응 책임 및 운영 피드백이 필요한 이유를 설명하는 것이 목표다. 단계별 작업 완료와 실제 사용 결과를 함께 살피는 방식이 비교 축이다.

| 독자 질문 | 수정 원고의 답 위치 |
| --- | --- |
| 개발과 운영은 각각 무엇인가? | 1장 `개발과 운영은 어떤 일인가`에서 개발, 운영과 배포를 정의한다. |
| 왜 함께 고려해야 하나? | `DevOps가 필요한 이유`에서 계속 바뀌는 소프트웨어의 안정적인 사용을 설명한다. |
| 정보가 끊기면 무슨 문제가 생기나? | `개발과 운영 사이에 정보가 끊기면`에서 늦은 실행 조건 전달과 운영 문제의 다음 개발 누락을 설명한다. |
| DevOps는 무엇을 바꾸나? | `DevOps에서는 어떻게 함께 일하는가`에서 계획부터 운영 결과까지 역할 참여와 책임 범위를 설명한다. |
| 자동화와 피드백은 왜 필요한가? | `협업을 자동화와 피드백으로 이어 가기`에서 합의한 반복 절차와 결과의 다음 개선을 연결한다. |

새 기능을 반복 배포하지만 사용자 오류가 개발 계획에 돌아오지 않는 팀의 문제는 운영 피드백의 단절이다. 첫 장의 세 번째와 다섯 번째 해설로 이 적용 질문에 답하는 자체검토를 수행했다. 실제 독자의 답변을 수집한 시험은 아니다.
