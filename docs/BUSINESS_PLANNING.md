## 주간 실행과 누적

매주 월요일 09:00(Asia/Seoul)에 이 대화의 heartbeat가 공식 자료를 검토한다.
앱 예약 `폴라리스 사업기획 주간 검토`(ID `automation`)를 ACTIVE로 생성하고 저장된 주기를 확인했다.
로컬 파일 작업을 위해 컴퓨터와 앱이 실행 중이어야 한다.
일일 GitHub Actions 수집은 사업 공고를 자동 파싱하지 않는다. `business`의
`planned` collector는 피드 미구현을 표시한다. 일일 브리핑/시간별 확인은 위 공개 경로를
직접 탐색하며, 사업 화면의 상세 검토·작성·수입은 기존 주간 에이전트 경로가 관리한다.

1. 운영 문서·출처 목록과 사내 최근 기록을 읽고 지난 확인일 이후 신규·정정·종료를 찾는다.
2. 원문·첨부 조건을 읽고 사실과 판단을 구분한다. 동일 원문 반복은 추가하지 않는다.
3. 공개 내용은 새 불변 JSON 배치로 작성한다. 기존 주제 변경은 같은 report ID의 새 revision,
   신규 주제는 새 ID로 추가하며 이전 판을 유지한다. 확인일만 바꿔 의미 없는 새 판을 만들지 않는다.
4. `research_publication.json`에 배치·신규 ID를 연결하고 `publish`로 공개 SQLite와 HTML을 갱신한다.
5. 사내 조사·미확인 조건은 외부 JSON을 `business-private --input`으로 수입한다.
   고객·가격·전략을 공개 배치나 자동화 알림에 복사하지 않는다.
6. 테스트·화면·링크·출처와 공개 경계를 검토한다. Signal Desk 계정·원격 guard를 통과한 경우에만
   관련 변경을 커밋·푸시하고 Pages 배포 결과를 확인한다. 무변경이면 조용히 종료한다.
   의미 있는 변경·실패·담당자 결정 필요만 알려준다. 신청 제출·고객 연락·견적 발송은 자동 수행하지 않는다.


`public_report_id`, `owner`, `due_on`, `customer`, `pricing`, `proposal`,
