사내 입력 JSON·메모·자료도 외부 작업 공간에 둔다. 공개 Git 저장소,
`data/raw`, 공개 DB, `site`, Actions artifact, GitHub Release 상태 백업에 넣지 않는다.
로컬 파일은 웹 로그인이나 팀 공유 서비스가 아니다. 접근 권한은 해당 컴퓨터의
파일 권한에 따르며, 팀 배포·접근 제어는 별도 환경이 필요하다.

`business-private`는 공개 config/DB를 열기 전에 별도 경로로 실행한다.
Git 트리 안의 경로와 공개 DB 연결을 거부하며, 사내 입력을 공개 보고서로
가져오려 해도 스키마가 달라 거부한다. 공개 상태 백업은 사내 테이블이 있으면
중단한다. 공개 exporter는 외부 사내 DB를 읽거나 병합하지 않는다.
사내 자료의 자동 익명화·공개 승격은 하지 않는다. 공개 원문에서 별도로 작성하고 검토한다.

## 제품 근거와 사내 확인

공개 제품 기준선은 AI DataInsight, Converter·ViewerPlus, WebOffice·Docs,
Mobile SDK다. 문서 구조화·AI 활용, 변환·뷰어 연동, 웹 편집·협업,
모바일 내장과 같은 고객 업무 후보를 도출한다. 제품별 플랫폼·배포·계약 조건을 확인한다.
공급자의 기능 설명은 독립 성능 검증이 아니다.

엔진/PC UI는 사용자 지정 기존 체크아웃을 읽기 전용 확인한다. 내부 코드·기능 선언·
브랜치·고객용 설정·파일 경로·검증 결과는 외부 사내 작업 공간에만 기록한다.
소스에 선언이 있거나 별도 제품 브랜치가 있다는 사실로 출하·지원·판매 가능을 확정하지 않는다.
고객 환경의 대표 파일, 권한·저장·성능·오류 처리·라이선스와 제품 담당자의 확인을 거친다.
이 사업 조사 요청은 엔진/PC UI 수정·빌드·커밋·푸시를 승인하지 않는다.

## 주간 실행과 누적

매주 월요일 09:00(Asia/Seoul)에 이 대화의 heartbeat가 공식 자료를 검토한다.
앱 예약 `폴라리스 사업기획 주간 검토`(ID `automation`)를 ACTIVE로 생성하고 저장된 주기를 확인했다.
로컬 파일 작업을 위해 컴퓨터와 앱이 실행 중이어야 한다.
일일 GitHub Actions 수집은 사업 공고를 자동 파싱하지 않는다. `business`의
`planned` collector는 피드 미구현을 표시하며, 주간 에이전트의 원문 검토·작성·수입 경로가 사업 영역을 관리한다.

1. 운영 문서·출처 목록과 사내 최근 기록을 읽고 지난 확인일 이후 신규·정정·종료를 찾는다.
2. 원문·첨부 조건을 읽고 사실과 판단을 구분한다. 동일 원문 반복은 추가하지 않는다.
3. 공개 내용은 새 불변 JSON 배치로 작성한다. 기존 주제 변경은 같은 report ID의 새 revision,
   신규 주제는 새 ID로 추가하며 이전 판을 유지한다. 확인일만 바꿔 의미 없는 새 판을 만들지 않는다.
4. `research_publication.json`에 배치·신규 ID를 연결하고 `publish`로 공개 SQLite와 HTML을 갱신한다.
5. 사내 조사·미확인 조건은 외부 JSON을 `business-private --input`으로 수입한다.
   고객·가격·전략을 공개 배치나 자동화 알림에 복사하지 않는다.
6. 테스트·화면·링크·출처와 공개 경계를 검토한다. Signal Desk 계정·원격 guard를 통과한 경우에만
   관련 변경을 커밋·푸시하고 Pages 배포 결과를 확인한다. 무변경이면 조용히 종료한다.
   의미 있는 변경·실패·담당자 결정 필요만 알려준다. 신청 제출·고객 연락·견적 발송은 자동 수행하지 않는다.

## 명령

```powershell
python -m housing_watch publish
python -m housing_watch business-private
python -m housing_watch business-private --input "D:\3_codex_docs\SignalDesk\BusinessPlanning\input.json"
```

사내 입력은 `{"schema_version":1,"records":[...]}`이며 `id`, `category`, `title`,
`status`, `checked_on`, `next_action`을 필수로 쓴다. 분야는 국책사업/영업 기회/경쟁사·시장,
상태는 확인 필요/검토 중/보류/진행/종료다. 날짜는 YYYY-MM-DD, 선택 필드는
`public_report_id`, `owner`, `due_on`, `customer`, `pricing`, `proposal`,
`technical_evidence`, `source_url`이다. 같은 ID의 변경만 새 revision으로 남긴다.
사내 화면은 읽기·검색·필터를 지원하고 입력 변경은 JSON 수입으로 관리한다.

초기 공개 3편은 조사 기준선이다. 정부 공고 전체 목록·실제 CRM·참여 자격 검증·실측
제품 비교를 완료한 것으로 보고하지 않는다. 초기 사내 3건도 확인할 업무이며 실제 고객을 뜻하지 않는다.
