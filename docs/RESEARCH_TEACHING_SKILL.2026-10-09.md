MCP Apps를 정의하기 전에 호스트·HTML 리소스·문맥을 사용한다. 본문은 곧바로

‘이미 있는 앱에서 확인’이라는 안내도 어떤 준비와 완료 결과를 뜻하는지 약하다.

## 교재형 설명에 보탠 원칙

독자가 필요한 지식과 이미 가진 지식의 차이를 설명 범위로 삼는다. 직함만으로

대상 독자·범위·목표를 분명히 하고 필요한 정보를 조직하는 데 참고했다.

개념 교재에 설치 명령을 억지로 넣지 않고, 실행 실습을 약속한 글은 재현 경로를 확인한다.

제목이 주요 내용을 알아보고 찾는 기준이 되도록 돕는다. 대상 이름과 평이한 기능을
함께 쓰며 제목·요약만으로도 내용을 설명할 수 있는지를 별도 검토한다.

[IES의 학습 지침](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)은 풀이 예제와 연습,
그림·언어 설명, 추상·구체 표현의 연결 등을 제안한다. 교재형 원고에는 일관된
사례와 이유가 있는 변형 풀이를 적용한다. 이 교육 지침이 Signal Desk의 독자 이해
개선을 실제 측정했다는 뜻은 아니다.

## MCP Apps 원고의 편집 목적

- 독자 질문: AI가 찾은 자료를 대화 안에서 직접 비교하고 고른 뒤, 그 자료를 AI에게 이어서 물으려면 무엇이 필요한가?
- 선행 지식: AI 대화창과 표·버튼은 사용해 봤지만 MCP·서버·문맥·JSON은 모른다고 가정한다.
- 학습 결과: MCP의 외부 조회와 Apps의 업무 화면을 구분하고, 같은 공고가 목록·상세·후속 답변에서 어떻게 이어지는지 설명한다. 정보가 낡았거나 선택이 어긋난 경우 확인할 경로를 구분한다.
- 글의 종류: 개념과 동작 원리를 배우는 설명. 공고 사례는 가상 값이며 설치부터 실행까지 따라 하는 SDK 튜토리얼을 약속하지 않는다.
- 설명 순서: 비교·선택 문제 → 외부 조회 규칙 → 사람이 읽는 공고 A·B·C → 조회 프로그램·AI 앱·화면의 역할 → 선택 전달 → 적용 조건. 규격 이름과 코드 형식은 선택 심화다.
