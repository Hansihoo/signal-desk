# DevOps 원고와 읽기 계층 재작성

사용자는 이전 문서가 곁가지와 반복으로 주제를 잃었으며 세부 목차가 시각적으로
구분되지 않는다고 지적했다. 제안한 개요를 승인한 뒤 r13으로 전체를 재작성했다.
독자의 결과는 DevOps의 뜻과 필요성을 설명하고, 동작하는 작은 서비스에 자동 검사,
버전 파일 생성과 로컬 배포, 상태 확인과 복구를 연결하는 것이다.

장 수와 세부 목차 수는 이번 독자 질문에 맞춘 선택이며 다른 주제의 필수 양식이 아니다.
기업 회고와 AI 설문, 심화 지표는 핵심 질문의 답이 아니어서 r13 본문에서 제외했다.
이전 판과 원문 근거는 보존한다. 전체 앱 코드는 선택 영역으로 옮겼으며 핵심 명령과
CI 설정, 기대 결과는 주된 읽기 경로에서 펼치지 않고 볼 수 있다.

## 원고와 화면 계약

- report-v1 필드는 추가하지 않는다. 설명은4개 장과 기존 block으로 저장한다.
- 원고 해시에 결합한 `topic_sections`가12개 세부 주제의 시작 위치와 anchor를 지정한다.
  H2는 장 번호와 제목, H3는 `3.2` 같은 세부 번호와 제목이다. 파일/명령은 캡션이다.
- 각 세부 주제의 요점을 먼저 보이고 이어 설명 문단과 필요한 코드, 결과와 이유를 둔다.
  요점의 개수를 고정하지 않는다. 문단의 내부 작성용 제목은 화면에서 숨긴다.
- 본문과 접힘 목차에 하위 링크를 제공한다. 상단에는 장과 세부 제목을 함께 표시한다.
- 다운로드 ZIP은 선택 영역에 보존한9개 코드 블록의 정확한 바이트로 생성한다.
  현재 `examples/`를 읽어 과거 판의 실습을 바꾸지 않는다. 경로/중복/코드 대응 검사를 거친다.
  생성 ZIP은 `site/preview/assets/devops-sort-r13.zip`이며 source로 커밋하지 않는다.
- r12와 그 이전 guide를 유지한다. 새 계층과 reader 표시 옵션은 r13 해시에만 적용한다.
  비어 있는 data anchor는 숨겨 이전 링크를 유지하고 내용 없는 비교 자료 제목은 만들지 않는다.

## 내용 검토와 수정

제목, 소개, deck, 요약과 highlights만 별도 파일로 먼저 읽고 전체 본문을 다시 읽었다.
작성자의 별도 자체검토이며 독립 검토/사람의 학습 시험이 아니다. 누락된 HTTP API/JSON의
첫 설명을 보강하고, 코드 분량 조정을 설명하던 문구를 서비스의 기능으로 고쳤다.
YAML에 없는 단계명 지칭도 실제 작업의 역할로 고쳤다.12개 질문의 답 위치와 근거를
quality의 answer_paths/claims에 연결했다. 형식 통과를 독자 승인으로 부르지 않는다.

사용한18개 출처의 원문 텍스트, 해시와 획득/검토 날짜는 r12와 동일하다. GitHub Python과
결과물, Google SRE 릴리스, Python HTTP 공식 페이지의 관련 절을 선별 재확인했으나
전체 재수집/전체 원문 재검토로 기록하지 않았다. HTML 생성은 근거 날짜를 갱신하지 않는다.

- 다운로드용9개 파일을 새 scratch에 풀어 원고의 PowerShell 명령을 실행했다.

  바이트,9개 파일, 모든 본문 anchor와 출처 링크를 검사했다.
- 실제 Chrome에서12개 세부 항목 이동과 현재 위치를 확인했다. 장32px/세부24px/캡션14px.
