## 내용과 출처

표는 정본 report-v1의 tables에 저장한다. CI 자체는 운영 배포 시점을 정의하지 않으며,
지속적 전달은 배포할 수 있는 상태를 유지하고 사람이 시점을 정할 수 있다. 지속적
배포는 조건을 통과한 변경을 개별 승인 없이 운영에 반영한다. AWS CI/CD와 DORA 전달의
관련 절을 대조했다. 전달 도식은 검사가 통과한 성공 경로이고 실패하면 배포를 중단하고
수정/재검사한다는 조건을 바로 아래에 설명했다. 자동 검사, 결과물 검사와 배포 후
확인은 별개의 결과다. 도식의 모든 단계가 자동 실행된다고 표현하지 않는다.

도식2개의 문구는 정본 steps 블록의8개 항목에서 직접 가져온다. visual guide에는
대응 경로, 표시 종류와 ID만 둔다. 복구 도식의 양끝에는 같은 releases/v1/v1.pyz가
보이며, 가운데v2파일과 구분된다. 기존 기능 동일 교체 연습, 정지 시간과 데이터
호환성 조건은 그대로다. 실습을 새로 실행했다거나 실제 장애 복구를 시험했다고
확장해서 주장하지 않는다. r13에서 실행 확인한 모든 코드/명령/기대 결과와 선택
영역9파일은 동일하며 ZIP 바이트도 동일하다.

원고 변경은 새 불변 r14 batch다. r13 및 이전의 표시 guide와 정본을 보존한다.
18개 출처의 텍스트/hash/획득/검토 날짜는 동일하다. AWS CI/CD, DORA 전달과 Google SRE
릴리스의 공식 웹 관련 절을 선별 재확인했고 전체 재수집으로 날짜를 갱신하지 않았다.
본문 첫 화면은 변하지 않아 r13의 별도 검토를 재사용한다. 추가한 표,8개 노드와 실패
문단, 인접 설명과 답 위치를 자체검토했다. 독립/인간 독해 시험은 수행하지 않았다.

## 렌더링과 검증

- `block_visuals`는 정본 steps 경로와 표시 ID를 검증한다. `topic_tables`는 해당
  세부 목차에 존재하는 표를 한번만 배치한다. 보고서 hash가 다르면 적용하지 않는다.
- HTML/CSS 도식으로 글자를 작게 줄여 이미지에 고정하지 않는다. 데스크톱에서는
  5개/3개 노드가 가로로 연결되고, 좁은 화면에서는 세로와 아래 화살표로 바뀐다.
  색상 외에 버전/경로/문장으로 의미를 표시한다. 순서 목록과 표의 헤더를 유지한다.
- renderer/briefing/publication21테스트27.644s 통과. 배치 gate1, local publish,
  audit15gated/30legacy. 위치/중복anchor/원고 문구/이전 표시와 ZIP 동일성 확인.
- 실제 Chrome에서 표가1.3, 도식이2.1/4.2에 표시됨을 확인했다. 넓은 실제2071px에서
  flow5열/recovery3열, 좁은 실제477px(요청430px와 다름)에서 각1열이며 가로 페이지
  넘침이 없었다. 표의415px 영역 안에서600px 표를 읽으며 키보드 접근이 가능하다.
  화살표6개의 방향과 노드 경계를 DOM에서 대조했고 복구의 첫/마지막 파일이 동일하다.
- 넓은 화면의 전달 노드와 화살표, 인접 설명이 담긴 PNG는 확인했다. 캡처는 상단 일부와
  빈 여백을 포함한 부분 결과다. 모바일 캡처는timeout/빈 화면으로 신뢰할 수 없어
  완전한 모바일 PNG 검수를 주장하지 않는다. 빈 캡처는 삭제하고 DOM 근거를 보존했다.
- brief 생성과390x1500 PNG 확인. 주택 review는 기존 활성 공고0건으로 FAIL,
  다른11개 항목은 통과했다. 이 작업에서 주택 원문 수집을 수행하지 않았다.
