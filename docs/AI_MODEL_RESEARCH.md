# AI 모델 리서치 운영

2026-10-08부터 전체 모델 정보를 누적 비교표로 유지하고 신규·변경 정보만 추가한다.
이 문서는 조사 대상·출처·수집·재검토의 운영 기준이다. 보고서 작성 품질은
[작성 가이드](RESEARCH_WRITING_GUIDE.md), 데이터 계약은 [RESEARCH_DATA.md](RESEARCH_DATA.md)를 따른다.

## 독자의 질문과 범위

Theo가 해결할 질문은 “현재 작업에 어떤 모델을 비교해 볼지, 새 모델이 나왔을 때
무엇을 다시 확인해야 할지”다. 기본 용어를 모를 수 있다고 가정한다. 모델과
Agent/Harness, 모델 제공 여부와 성능, 공개 벤치마크와 실제 작업 결과를 구분할 수
있도록 설명한다. 벤치마크만으로 업무 적합성이나 월 구독 작업량을 확정하지 않는다.

| 조사 항목 | 먼저 확인할 근거 | 기록할 조건 |
| --- | --- | --- |
| 현재 모델과 제공 상태 | 제공자의 공식 모델 목록·수명 주기 | 정확한 모델 ID, API/앱/파트너, 일반·제한 제공, 확인일 |
| 신규 모델·중요 변경 | 공식 출시 발표·모델 카드·변경 이력 | 발표일, 실제 이용 가능일, 이전 모델 대비 변경, 적용 대상 |
| 사양·가격 | 공식 사양·가격·정책 | Context, 입력·출력 단가와 단위, 캐시·할인·기간, 제한 |
| 코딩·에이전트 성능 | 평가 주체의 원문·방법론 | 모델·추론 설정·Agent/Harness·평가판·표본·확인일 |
| 로컬·오픈웨이트 | 공식 저장소·모델 카드·라이선스 | 가중치·양자화·메모리 조건·상업 사용 제한 |
| 작업 적합성 | 동일 작업군으로 실행한 측정 | 입력·성공 기준·회귀 검사·개입·실패/재시도 비용 |

## Theo의 기존 자료

원본은 공개 [theo-s-han/research-analysis](https://github.com/theo-s-han/research-analysis)다.
원본 저장소는 읽기 전용으로 참조한다. 이 요청은 그 저장소의 수정·커밋·푸시를 승인하지 않는다.

- 통합 기준표: [주요 LLM·코딩 모델 통합 비교](https://theo-s-han.github.io/research-analysis/docs/llm-models/).
- 전체 모델 데이터: 공개 `materials/주요 LLM 모델.html`의 원래 표와
  `llm-model-research.js`에 포함된 가이드 데이터, 제공 목록·AA 모델·Agent·Cursor·실사용 JSON을 직접 읽는다.
- 수집 메타데이터: 공개 사이트의 `catalog.json`. 관련 보고서 제목·설명·slug·날짜·HTML SHA-256을 별도 참조로 제공한다.
- 모델별 가이드와 평가 자료: `모델 리서치`·`벤치마크` 분류 전체, 그리고 설정에 명시한 모델 선택·비용·사용량 자료.
- 원본 제공 목록: `content/llm-model-availability.json`. 공개 평가 스냅샷은 `llm-model-benchmarks.json`, `llm-agent-benchmarks.json`, `llm-cursor-benchmarks.json`.

[config/ai_model_research.json](../config/ai_model_research.json)이 가져오기 범위를 소유한다.
새 자료가 원본에서 `모델 리서치` 또는 `벤치마크`로 게시되면 자동으로 포함된다.
다른 분류의 관련 자료는 `additional_slugs`에 추가한다. 모델 추론 설정 안내(Windows Max)를 포함하며, 일반 에이전트 패턴 자료는 자동으로 포함하지 않는다.

## 실제 수집과 저장

```powershell
# 전체 모델 표를 갱신하고 누적 기록을 JSON으로 내보내기
python -m housing_watch ai-models --collect

# 기존 자료·신규 모델 후보를 포함한 모든 공개 소스 갱신과 데이터 내보내기
python -m housing_watch research-data --collect

# AI 자료만 갱신하고 최근 7일 이슈 브리핑 생성
python -m housing_watch issues --days 7 --limit 18 --per-page 6 --width 645 --height 1500

# 저장된 전체 자료와 검토된 보고서로 로컬 사이트 생성
python -m housing_watch publish
```

`collect_ai_news`가 기존 공식 RSS/릴리스, 일반 AI 검색, 신규 모델 전용 검색,
Theo 자료 목록과 전체 모델 데이터를 갱신한다. 기존 일일 GitHub Actions의
`publish --collect`에도 포함된다. 이 변경을 커밋·푸시한 뒤 배포해야 공개 자동 수집에 적용된다.
신규 모델 검색은 주요 제공자와 `new model / model release / model launch / model update`
및 요청 기간을 조합한다. Google News 결과는 발견 후보다. 원문을 읽기 전 공식
확인 완료로 표시하지 않으며, 모든 모델 출시를 빠짐없이 찾는다는 보장은 없다.
`--limit`은 뉴스 후보 수를 제한한다. 기존 비교 자료 목록은 기간·뉴스 한도와
별도로 전체 범위를 저장하고, 최근 이슈 화면에서는 자료 수정일로 기간을 거른다.

원본 catalog는 `data/raw/ai_news/model_research/`에 보관한다. 정규화한 제목·설명·주소·
날짜·원본 해시·출처 성격은 SQLite `news_items`에 `ai_theo_model_research`로 저장한다.
분류는 `AI 개발 → LLM 모델`이다. 날짜는 원본 수정일과 기준일을 따로 보존한다.
수집일을 발표일이나 사실 확인일로 대신하지 않는다. 누락된 기준일은 미표기로 남긴다.

같은 slug는 같은 자료로 유지하고, 내용 해시나 메타데이터가 바뀐 경우만 갱신한다.
제목이 같아도 다른 slug는 별도 자료다. 다른 AI 피드의 같은 제목과도 섞지 않는다.
자료 목록 수집 실패·잘못된 날짜·경로·중복 slug는 경고 또는 실패로 기록하며
기존 자료를 지우지 않는다. 원본에서 빠진 자료도 자동 삭제하지 않는다.

모델 원본 7개 파일은 `data/raw/ai_news/model_ledger/`에 내용 해시별로 보존한다.
동일 파일을 다시 받을 때 새 복사본을 만들지 않는다. 공유 JS·평가 JSON은 catalog와
독립적으로 읽으므로, 문서 제목·HTML이 그대로여도 평가 수치 변경을 감지한다.
누적표 수집기는 JS 끝부분의 JSON 데이터만 파싱하고 실행하지 않는다. HTML은 `tbl`의 텍스트·출처·조건을 추출한다. 별도 문서 복제는 아래 격리된 본문 페이지 계약을 따른다.

SQLite `model_observations`는 현재 모델·설정·평가별 정보,
`model_observation_revisions`는 변경 전후의 불변 판,
`model_sync_runs`는 성공·실패·증분 건수를 소유한다. 같은 원본 ID·평가판은 같은
기록이다. 평가판이 바뀌면 새 기록으로 남긴다. 서로 다른 추론 설정·fallback·
Harness·AA 모델/Agent/Cursor 평가를 같은 값으로 합치지 않는다. 표 행 순서가
달라져도 모델 정보 변경으로 기록하지 않는다. 실제 수집 시각과 원자료 날짜도 구분한다.
`checked_on` 날짜 값은 자료 종류와 함께 읽는다. 최신 평가·제공 목록은 원문 확인일,
이전 모델 가이드는 `observed` 기준일, 실사용 기록은 `measuredAt` 측정일이다.
화면은 이를 `원자료 날짜`로 표시하고 상세에서 날짜 종류를 구분한다.

7개 파일 모두 수집·파싱에 성공한 뒤 한 트랜잭션으로 반영한다. 실패하면 이전
비교표를 유지하고 실패 상태를 표시한다. 없어진 행은 삭제하거나 제공 중단으로
단정하지 않고 `원본에서 빠짐 · 이전 정보 보존`으로 표시한다. 누락 값은 0으로
채우지 않으며, 추정 AA Intelligence는 실측 칸에서 제외하고 원본 상세에 보존한다.
비율은 %로, Agent 시간은 분으로 표시하되 원본 수치·단위는 함께 보존한다.

## 리서치 하위페이지와 관리 경로

목차와 메인의 자료 수는 현재 문서 페이지로 집계한다. 전체 모델 비교표는 1페이지,
모델별 가이드·평가 자료는 `model_pages.pages`의 현재 문서 수다. 원문 내부의 모델·
설정·평가 행 수와 이전 판·별칭 URL은 페이지 수에 포함하지 않는다. 상위 목차의
분야 수에는 이 자료 페이지도 더한다. 비교표 내부의 필터 결과·행 수는 별도 유지한다.

- 리서치 메뉴: `개발 동향 → AI 모델·API → 전체 모델 비교표`.
- 현재 페이지: `site/preview/ai-models.html`; 분야 경로: `site/research/ai/models/index.html`.
- 전체/사양/AA 모델/Agent/Cursor 보기, 개발사·추론·도구·자료·이용 방식·제공 상태·원본 상대 구간 필터, 로컬 표시·AA 평가 제한, 검색·정렬·열 선택·CSV 저장.
- 모델 이름을 누르면 전체 사양·조건·출처·원본 값과 이전 판의 변경 항목을 확인한다.
- 처음 가져온 기록은 기준 자료다. 이후 새 행과 내용이 바뀐 행만 변경 목록에 표시한다.
- 새 소식은 별도 검토 대기로 모은다. 뉴스의 제목·요약으로 사양·점수를 추측해서 채우지 않는다.
- `ai-models`와 `research-data`는 JSON의 누적 기록을 내보내며, `publish`는 SQLite에서 화면을 재생성한다.
- 클라우드의 기존 SQLite/원본/사이트 백업에 새 누적 표와 판별 기록도 포함된다.

공식 원문을 확인한 신규 정보는 `python -m housing_watch ai-models --input <JSON>`으로
추가한다. `schema_version: 1`, `records` 배열 안에 `id`, `model`, `provider`,
`source_url`, `checked_on`, `fields`를 둔다. `fields`의 `kind`(사양/평가 등),
`suite`(사양판/평가판), `condition`은 필수이며 원문의 제공 조건·실행 환경을 적는다.
숫자의 단위는 화면 계약에 맞춘다(비율 %, Context 토큰, 파라미터 B, 비용 USD,
Agent 시간 분). `fields`에 값을 넣지 않으면 미측정으로 유지한다. 근거 URL·
확인일 없이 가져오기는 거부한다. 도구·추론 설정·평가판이 바뀌면 새 기록으로 저장한다.
`candidate_ids: ["news-123"]`처럼 해당 뉴스 ID를 연결하면 검토 대기 목록에서 제외한다.
전체 필드 목록과 근거 원문을 함께 기록하고 `publish`로 비교표를 재생성한다.

이 검토 자료는 `reviewed` 출처로 별도 보존한다. 이후 원본 표를 다시 가져와도
삭제하거나 덮어쓰지 않는다. 같은 `id`·모델·설정·Harness·평가판의 내용 변경은
다음 판으로 저장한다. 이 경로는 원본 저장소를 수정하지 않으며, 작성 에이전트가
원문을 검토했다는 사실을 대체하지 않는다. 벤치마크를 다시 실행하는 기능도 아니다.

## 후보에서 검토된 보고서로

1. 독자가 비교할 작업과 기존 기준 모델을 정한다. 신규 모델 자체를 순위 1위로 가정하지 않는다.
2. 후보의 원문을 열어 제공자 공식 발표·모델 목록·가격·제한·종료일을 확인한다.
3. 이전 자료와 비교해 신규 출시·제공 조건·사양·가격·평가 변경을 분리한다.
4. 수치는 같은 모델 ID·추론 설정·평가판·Harness·단위일 때 비교한다. 누락은 0으로 채우지 않는다.
5. 원문 위치·발표일·확인일·조건과 사실/자가보고/편집 판단/미측정을 구분해 작성 메모에 남긴다.
6. 실제 작업 권고에는 대표 입력과 성공·실패·회귀 기준을 설명한다. 실행하지 않은 비교는 개념 예시로 표시한다.
7. 의미 있는 변경만 기존 보고서 ID의 새 불변 배치 또는 새 주제의 새 ID로 발행한다.

검토된 모델 보고서는 `개발 동향 → AI 모델·API` 아래에 둔다. 첫 연결 보고서는
`llm-model-comparison`이며, 비교 방법을 설명한다. 실제 누적 정보는 별도 전체 모델 비교표에서 관리한다.
수집된 항목은 검토된 보고서와 별개다. 일일 수집이 심층 분석이나 공식 모델
제공 상태 재검증을 자동으로 완료하지 않는다.

## 모델별 본문과 자동 페이지 추가

`python -m housing_watch model-pages --collect`는 현재 범위의 전체14문서와 필요한
동일 사이트 JS/CSS를 수집한다. 각 HTML의 SHA-256은 catalog와 일치해야 한다.
중복 수집은 판을 추가하지 않으며, 본문·메타데이터·공유 자산 변경은 새 불변 판이다.
개별 문서 실패는 기존 판을 보존하고 성공 문서만 반영하며 실패 상태를 기록한다.
이전 원본에 존재한 모델을 최초 수집 당시 신규 출시로 처리하지 않는다.

SQLite `model_pages`, `model_page_revisions`, `model_page_runs`에 원문 전체·정규화한
제목/분야/원자료 날짜/출처와 공유 자산을 보존한다. HTML/자산은 단순 텍스트 데이터로
수집하며 생성기는 검증된 동일 디렉터리의 JS/CSS만 본문에 묶는다. 본문은
same-origin 권한 없이 sandbox iframe에서 실행되어 부모 페이지를 조작하지 않는다.
네트워크 fetch와 양식 전송은 차단하며 원본 표 필터·정렬·CSV·차트·설명을 유지한다.
원본 테마 설정용 storage는 격리된 메모리로만 대체한다. 문서의 사실을 재작성하거나
독립 공식 검증을 완료한 것처럼 날짜를 변경하지 않는다.

- 자료 목록: `site/preview/ai-model-guides.html` 및 `site/research/ai/models/guides.html`.
- 모델 자료: `site/preview/model-guides/<slug>.html`.
- 불변 문서: `site/preview/model-guides/<slug>-r<N>.html`.
- 원본 전체 표도 `model-guides/llm-models.html`에서 기존 도구·개발사·이용 방식·상태·
  상대 구간·로컬·AA 등 원본 전용 필터와 함께 읽을 수 있다.
- 신규 catalog slug는 다음 일일 수집에서 자동으로 추가하고 현재·이전 문서를 보존한다.

Theo에 아직 없는 공식 신규 모델은 기존 v1 연구 보고서 JSON 계약과 작성 가이드로
검토하여 새 stable report ID 및 `개발 동향 / AI 모델·API`에 발행한다. 새 불변 입력
배치를 `config/research_publication.json`에 등록한다. 원문과 가격·사양·추론 설정·
Harness·평가판·단위·날짜·미확인 항목을 설명하고 기존 모델과의 비교 조건을 맞춘다.
검토한 표 사실의 입력(JSON `schema_version:1,records`)은 `config/ai_model_publication.json`
의 새 `batches:[{id,path}]` 항목에도 등록한다. `path`는 같은 config 폴더의 공개
JSON 파일명이다. 이미 적용한 배치 수정은 거부한다. 로컬/클라우드 `publish`와
`research-data`는 동일 불변 배치를 한 번만 적용하므로 generated DB를 Git에 넣지
않고도 공식 추가 사실과 새 페이지를 배포에 보존한다.
검토 기록에는 모델/페이지·비교한 이전 상태·공식 근거·확인일·변경·배포 결과를 남긴다.
