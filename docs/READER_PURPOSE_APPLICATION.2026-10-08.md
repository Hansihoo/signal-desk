# 독자 목적을 메인에 적용한 첫 사례

## 편집 목적

- 독자의 질문: MCP Apps는 어떤 일을 편하게 만들며, 내 업무에 도입하려면 무엇을 구분해야 하는가?
- 전제 지식: AI와 대화하고 HTML 화면을 본 경험은 있지만 MCP의 구성 요소는 모른다.
- 읽은 뒤의 목표: 공고 목록 조회 → 화면 표시 → B 선택 → 상세 조회의 경로를 설명하고, 데이터 수정·화면 수정·AI 대화 전달을 구분한다.
- 이번 범위: 메인 표시 방식과 MCP Apps 한 편. 나머지 열다섯 보고서는 본문을 다시 쓰지 않는다.

## 실제 적용

대표 글을 `mcp-apps-workflows`로 바꿨다. 메인 제목은 공고 비교·선택이라는
구체적인 업무를 말하고, 개요와 항목에는 무엇을 보여주고 무엇을 별도로
연결해야 하는지 넣었다. 오른쪽 표는 공식 기능을 공고 업무에 대입한 예시다.
실제 공고·작동하는 제품 화면으로 오인하지 않도록 표 아래에 명시했다.

분야별 최근 글과 게시판 목록에는 원래 데이터의 `deck`을 보여준다.
짧은 `highlights` 두 개를 이어 붙이던 방식보다 글의 내용을 문장으로 알 수
있도록 했다. 다른 보고서 원문 데이터까지 보강한 것으로 해석하면 안 된다.

본문에는 다섯 장의 `explanation`을 추가했다. 기본 용어, 일관된 A·B·C 사례,
데이터와 HTML의 역할, 클릭과 대화 전달의 차이를 요약과 데이터 사이에서
바로 읽는다. 시간 예제·구현 준비·응용 연습 세 장은 `learning`으로 남긴다.
이 분리는 필요한 설명을 숨기지 않고 선택적인 깊이를 제공하기 위한 것이다.

버전 1 데이터 계약에 `explanation`을 선택 필드로 추가했다. 기존 장/블록
검증을 재사용하며 CSS·레이아웃 정보는 담지 않는다. 없는 보고서는 기존
읽기 구조를 유지하고 비어 있는 본문 링크·영역을 만들지 않는다.
문단의 빈 줄은 실제 문단으로 렌더링한다. 내용은 HTML로 해석하지 않는다.

입력은 `config/development_reader_purpose.2026-10-08.json`의 새 불변 배치다.
기존 보고서 ID와 현재 URL을 유지하고 MCP 3차를 발행했다. 이전 MCP 1·2차와
다른 열다섯 보고서의 내용은 보존한다. 수집 데이터·본문과 Editorial 표현은
계속 별도로 관리한다.

## 내용 검토

2026-10-08 공식 [개요](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html),
[MCP 구조](https://modelcontextprotocol.io/docs/2026-07-28/learn/architecture),
[Apps 사양](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx),
[시간 예제](https://apps.extensions.modelcontextprotocol.io/api/documents/quickstart.html)를 재확인했다.

- 제공자와 읽는 주체: 서버가 HTML을 제공하고 호스트가 읽어 View를 실행한다.
- 예시 일관성: 같은 공고 A·B·C, 선택값 B, 목록·상세 결과의 역할을 끝까지 유지한다. 특정 함수 시그니처를 임의로 실행 가능한 튜토리얼로 제시하지 않는다.
- 클릭의 의미: 도구 호출·문맥 갱신·메시지 전송을 구분한다. 자동으로 AI가 응답한다고 주장하지 않는다.
- 적용 조건: 호스트의 Apps 지원을 별도 확인한다. 생산성 향상을 측정했다는 주장을 넣지 않는다.

## 이해 가능성 자체 검토

메인만 읽으면 비교·조회·선택 전달의 의미를 확인할 수 있다. 보고서의 본문만
순서대로 읽어도 약어와 구성 요소를 도입한 뒤 공고 흐름에 연결된다. 필수
설명은 닫힌 `details`에 들어 있지 않다. 공식 예제는 선택 학습으로 이어진다.
이는 작성자의 자체 검토이며 실제 독자 테스트는 수행하지 않았다.

## 출력 검증

74개 테스트, compileall, JS 구문 검사, publish, brief, summary desk, review가
통과했다. brief/desk 이미지와 실제 브라우저의 메인·본문을 확인했다.
이 검사는 데이터 보존·렌더링·동작에 대한 근거이며 독자의 이해를 증명하지 않는다.
실제 로컬320/390px 메인·본문·펼치기에서 가로 넘침이 없었다. 키보드 Enter/Space,
펼친 학습 본문 검색, 해커톤 상위 분류 두 글 조회, 공식 시간 예제 이동·복귀,
이전 MCP 2차 이동을 확인했다. 40개 HTML의 내부 링크·자산1693건과 문서링크37건이
해결된다. 본문은 CSS/DOM 확인에서도 닫힌 영역에 들어 있지 않았다.

소스 `1c3119a`의 [배포37720532179](https://github.com/Hansihoo/signal-desk/actions/runs/37720532179)는
성공했다(1분39초). 공개 데이터967건/보고서16편/누적27판의 모든 보고서와 판 번호가
로컬과 같고, CSS `66e51886df96`도 일치한다. 공개 메인→보고서, 본문5장·추가학습3장,
Enter 펼치기와 콘솔 오류 없음, 공개 이전 MCP 2차를 확인했다.
공개 캡처는 실제1280px다. 공개390px 요청은1280px로 남았으므로 공개 모바일
검증으로 집계하지 않는다. 동일 CSS/내용의 로컬320/390px 검증을 근거로 삼는다.
화면 폭 설정은 복원했다. 메인·대표 보고서 탭과 캡처·단일 HTML 보존본을 유지했다.
