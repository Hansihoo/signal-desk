# DevOps 목차와 본문의 대응 재검토

기존 r8의9개 장과51개 소제목/코드 블록, 요약과 결론,3표와2그래프를 실제 읽고 각각의 질문에 답하는 내용을 대조했다. 첫 장만 고치는 것으로 끝내지 않고 빠진 설명과 자료의 성격, 실제 실습 범위 및 과제 풀이를 수정한 r9를 다시 읽었다.

## 요약

2장과7장은 제목에 맞는 내용을 설명해 유지했다. 나머지7개 장은 설명 누락이나 제목/범위의 어긋남을 고쳤다. r9는9개 장과55개 소제목/코드 블록이며, 새 블록은 협업 원칙과 평상시 운영, AI 연구의 목적 및 원격 설정 전 준비/후 확인의 분리다. 소제목 수나 시험 통과를 이해의 증거로 사용하지 않는다.

| 장 | 발견한 문제와 조치 |
| --- | --- |
| 1. DevOps는 무엇이며 왜 필요한가 | 개념 장 끝의 조사/교재 자료 소개 반복을 제거하고 팀별 실천 범위로 마무리했다. |
| 2. DevOps와 CI/CD는 어떻게 다른가 | 정의와 차이, 가정과 목적을 밝힌 사례 및 비교표가 대응한다. 내용 유지. |
| 3. DevOps에서 중요한 것은 무엇인가 | 검사 절차에 치우쳐 빠진 공통 목표와 대응 책임의 원칙을 보완했다. |
| 4. 기업 사례와 운영 원칙에서 무엇을 배울 수 있는가 | 두 기업 회고와 Google SRE 교재의 원칙을 구분하도록 장/소제목/요점/표를 수정했다. |
| 5. 첫 자동 검사는 어떻게 만들고 배포로 연결하는가 | 첫 검사와 배포 연결이라는 실제 범위로 제목을 좁히고 준비→설정→확인 결과로 배치했다. |
| 6. 만든 뒤에는 어떻게 운영하는가 | 장애 대응뿐 아니라 평상시 관리도 설명하며 가상 장애의 선행 입력 조건을 밝혔다. |
| 7. 도입 전에 무엇을 고려해야 하는가 | 제품과 환경, 권한/운영 주체/복구/비용의 도입 조건이 대응한다. 내용 유지. |
| 8. 전달 성과를 무엇으로 측정하고 연구를 어떻게 읽는가 | AI 연구를 전달 성과와 연결하는 이유를 설명하고5개 지표의 읽는 예시를 완성했다. |
| 9. 무엇부터 공부하고 어디를 참고하면 되는가 | 개념부터 공부하도록 순서를 보강하고 네 과제에 네 풀이를 대응시켰다. |

### 2. DevOps와 CI/CD는 어떻게 다른가

| 소제목 또는 코드 | 본문에서 답하는 내용 | 조치 |
| --- | --- | --- |
| 먼저 알아둘 용어 | 저장소와 커밋, 빌드 결과물, 테스트와 두 환경을 먼저 정의한다. | 유지 |
| CI: 변경을 오래 쌓아 두지 않는다 | 자주 통합하고 자동 검사하며 실패를 고치는 CI의 범위를 설명한다. | 유지 |
| Continuous Delivery: 필요할 때 배포할 수 있다 | 지속적 전달은 필요할 때 배포할 수 있는 준비 상태를 유지한다. | 유지 |
| Continuous Deployment: 운영 배포도 자동으로 시작한다 | 지속적 배포의 변경별 수동 승인 없는 운영 반영과 외부 공개 절차의 제한을 설명한다. | 유지 |
| 정렬 오류 예시로 CI/CD 구분하기 | CI/CD 구분을 확인하려는 목적과 가상 서비스, 배포 준비와 운영 반영의 차이를 밝힌다. | 유지 |

| --- | --- | --- |

| 작은 변경을 검사하는 이유 | 작은 변경은 실패 원인 범위를 좁히며 필요한 검사는 유지한다. | 유지 |
| “내 PC에서 통과”를 팀의 결과로 바꾸는 방법 | 명령과 언어/의존성 버전을 공유하고 검사한 결과물을 식별한다. | 유지 |

| 완료의 범위를 운영까지 넓힌다 | CI 성공 이후 사용자 영향과 운영 문제를 다음 개선에 반영한다. | 유지 |
